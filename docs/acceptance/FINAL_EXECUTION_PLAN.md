## Действия, которые нельзя безопасно считать закрытыми сейчас

- Создание conversion configuration `WEBPAGE/SIGNUP` не равно работающему `sign_up` tracking и не порождает TEST serving conversions. Не писать фиктивные регистрации и не заявлять метрики.
- PMax fixture не равна исходному editing; один theme edit не равен всем шести профилям. Отсутствие owned audience/BRANDS — внешний prerequisite, а не API limitation.
- Изображения и копия для старой марки HolyMedia MCP должны быть сверены с утверждённым брендом HolyPilot до реального PMax preview. Не подменять логотип и не утверждать Google policy approval по локальному mock.
- Произвольное клонирование не подтверждено Search Clone 7/7; текущий bounded PAUSED Search/RSA профиль сохраняется как LIVE PASS.
- Без устойчивого TEST + production post-start guard нет разрешения ни на один cutover; предыдущие Web попытки исчерпаны и откатились. Capacity на 2 GiB пока **UNKNOWN в смысле доказательства**, общий итог **CONDITIONAL**.
- Billing, TikTok/Yandex report parity, GSC/GA4, SEO и вся общая готовность HolyPilot — отдельные product направления вне первоначального Google Ads Write ТЗ; их нельзя незаметно добавлять в denominator 100% исходного ТЗ.

## Один будущий Codex-промпт (черновик; сейчас не исполнять)

> Продолжи HolyMedia MCP/HolyPilot на точных текущих ветках и прочитай `docs/acceptance/FINAL_ORIGINAL_TZ_GAP_AUDIT.md`, `docs/operations/ZERO_COST_100_PERCENT_FEASIBILITY.md`, исходные 336 параграфов и сохранённые evidence. Цель — максимально закрыть остаток исходного Google Ads Write ТЗ на имеющемся VPS без расходов, не изменяя main/production автоматически. Работай шестью batches из `FINAL_EXECUTION_PLAN.md` в одном задании. Сначала заверши весь независимый code/mock/integration/security пакет и exact-SHA CI/image build; проверь brand-only diff и внешние Google prerequisites до deployment. Никакие TEST/production ресурсы, guards, OAuth secrets и Google account state не изменяй без нужной отдельной owner stop-point. Перед любым cutover: zero active approvals/commits, protected backup+rollback, достаточный диск после pull, полный resource guard, production health/latency, затем один container replacement без двух экземпляров; при fail один rollback и STOP для этой попытки. TEST Web, TEST API, production Web и Google commits имеют отдельные разрешения. Не переносить Web swap policy на API. Не обходить browser approval, exact TEST origin/account, default-OFF flags и production write OFF. После допустимого TEST deployment проведи fresh provider READ/validate-only, но перед каждым Google commit представь JIT immutable preview с BEFORE/AFTER, URL, expiry и дождись отдельного ручного HolyMedia approval и явного разрешения владельца; при ambiguity только read-only reconciliation. Сначала успешная регистрация HolyPilot как ConversionAction/goal (без фиктивного event tracking), затем PAUSED PMax fixture, затем все шесть PMax edit profiles и оставшиеся Stage 0–4 профили с отдельными restores. Не повторяй исторические 20/20, Search Clone или destructive delete ради evidence. Для R/S найди existing client prompt evidence; не мутируй Google ради скриншотов. Если full-stack guard/Google ресурсы недоступны, продолжай всю offline работу и отметь точный внешний blocker. Обнови матрицу, handoff, CI/security/rollback evidence и дай честный итог без объявления 100% до реального provider proof. Production Google Write и main не меняй без нового отдельного разрешения.

**Управленческий ответ:** один большой Codex task технически может вести все batches с ожидаемыми ручными остановками. Он **не** может законно превратить разные Google approvals, production release или недостающий реальный conversion ресурс в одно предварительное разрешение. Самый быстрый безопасный старт — полностью закрыть batch 1 и внешний blocker inventory без единого deployment; затем решать каждый следующий cutover по новым измерениям, а не по надежде на свободный диск.
