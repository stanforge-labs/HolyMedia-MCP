# Bounded G / I / J READ-only discovery

Enable only the existing source-pinned isolated READ runtime with `STAGE234_DISCOVERY=true`. Default readiness behavior is unchanged. The ordinary encrypted context, scoped account, TEST/hierarchy/fixture proof, all-write-flags-OFF, unchanged-before/after comparison and transport READ limit remain mandatory. No new key/OAuth, preview, approval, mutation, asset, audience or goal is created. This package was mock-tested only; no remote/provider call was executed by its author.

The runner enrolls only exact locally-generated templates after fresh proof. The request guard independently checks those templates, exact TEST customer, Google v24 origin, login MCC, POST searchStream and a body containing only query. Arbitrary GAQL, foreign customers and mutate/validate-only requests remain rejected.

- G: at most 20 actual PAUSED SEARCH auto-strategy campaigns. A 21-row sentinel blocks further proposals. Read at most 100 positive ENABLED keywords from those owned PAUSED SEARCH_STANDARD groups, with actual explicit raw CPC. Dynamic effective CPC is not guessed. Each proposal still requires a later stock fresh preview and separate human approval; discovery is not authorization.
- I: separate IN_MARKET and AFFINITY keyset queries ordered by provider ID, 100 accepted rows plus a sentinel per page, maximum five pages / 500 rows per taxonomy. The sentinel is read again on the next page, never silently discarded. Ineligible, duplicate, foreign, non-monotone or malformed proof fails closed. Bound exhaustion blocks proposals even if a candidate was observed. Empty bounded responses are not a global absence claim. Existing OBSERVATION and audience eligibility guards stay authoritative.
- J: resolve actual Astana City first; only then enroll the exact parent-scoped District/Borough/Municipality query. Geo constants provide no center coordinates. The only discovered center comes from an existing same-fixture provider PROXIMITY criterion; no address geocoding, coordinates or resource IDs are invented. Missing center/district proof remains BLOCKED. Radius plans are not constructed from this discovery alone.

Output is a sanitized nested `discovery` section in the existing evidence file, with candidate identities/typed proposals, coverage bounds, preserved criterion digest, safe error codes and no LIVE PASS. Per-HTTP READ totals remain those counted by the existing runner. All writes remain zero. No absence claim or permission to create missing prerequisites is implied. Keep historical evidence and runtime source/image provenance unchanged.

Primary v24 field checks: [user_interest](https://developers.google.com/google-ads/api/fields/v24/user_interest) documents ID as filterable/sortable and taxonomy as filterable; availability is selectable but not filterable, so eligibility is evaluated from actual returned metadata. [geo_target_constant](https://developers.google.com/google-ads/api/fields/v24/geo_target_constant) documents `parent_geo_target` as filterable and geo ID as sortable. Resource-name ordering is not assumed; there is no arbitrary provider query input.
