## 1. Регистрация MCP tools и выбор провайдера

- `apps/api/src/mcp/mcp.controller.ts:30-145`: `@Post("mcp")` принимает JSON-RPC, `tools/list` вызывает `McpService.tools()`, `tools/call` — `McpService.call()`. Контроллер требует Bearer service token/OAuth, расходует лимит и пишет событие `mcp_tool_executed`. `@Get("mcp")` не является SSE-транспортом.
- `apps/api/src/mcp/mcp.service.ts:31-172,333-345`: инструменты перечислены в `V1_COMPATIBLE_MCP_TOOLS`; для большинства input schema остаётся общим объектом с `additionalProperties: true`. По имени tool срабатывает прямой `switch`, `compatRead()` либо `COMPAT_PREVIEW_OPERATIONS` → `compatPreview()`.
- `apps/api/src/mcp/mcp.service.ts:22-29,298-311,1819-1852`: строковые алиасы `google_ads`/`meta_ads` превращаются в `GOOGLE_ADS`/`META_ADS`; `account()` находит включённый `ProviderAccount` в workspace и проверяет ограничение service token по account IDs. Для preview используется `campaignProvider()` — только эти два провайдера.
- `apps/api/src/providers/provider.registry.ts:23-89`: registry создаёт `GoogleAdsAdapter` и `MetaAdsAdapter`, связывает adapter с definition. `ProviderService` получает adapter по provider ID; `readContext()` (`provider.service.ts:1393-1425`) расшифровывает credential, обновляет истекающий OAuth token, находит account и передаёт adapter целевой customer ID, валюту и `loginCustomerId` из metadata.

## 2. Capabilities, supported objects и запрет Google write

- `apps/api/src/providers/adapters/google.ads.ts:33-65`: `googleAdsDefinition()` ставит `read: configured`, `write: false` всегда; статус — `available` только если заданы OAuth client ID/secret, redirect URI **и developer token**. После sunset token это устаревшая локальная зависимость.
- `apps/api/src/providers/adapters/meta.ads.ts:46-59` определяет возможности Meta (`write` зависит от конфигурации OAuth `ads_management`, но сам по себе не снимает policy commit); `apps/api/src/providers/provider.registry.ts:29-62` возвращает definitions через `ProviderService.listProviders()` (`provider.service.ts:76-78`). `get_provider_capabilities` берёт этот список (`mcp.service.ts:566-570`).
- `list_supported_objects` не читает provider-specific декларацию: `McpService.supported()` (`mcp.service.ts:1758-1778`) всегда даёт `account`, `campaign` и при `read=true` — `metrics`. Поэтому у Google сейчас нет `keyword`, `ad_group`, search terms или negatives в MCP supported objects.
- `McpPreviewService.commitPolicyReason()` (`mcp-preview.service.ts:484-506`) отвергает любую запись, если provider не `META_ADS`; общий `V2_PREVIEW_ONLY=true` и `V2_CONFIRMED_WRITE_ENABLED=false` по умолчанию (`packages/config/src/index.ts:70-79`). У `GoogleAdsAdapter` нет `mutateCampaign`; `ProviderService.mutateCampaign()` (`provider.service.ts:967-998`) дополнительно требует mutation adapter. Capability `write=false` — описание, а фактический запрет находится в этих слоях.

## 3. Существующий Meta write flow: что можно и нельзя переиспользовать

`*_preview` из `COMPAT_PREVIEW_OPERATIONS` (`mcp.service.ts:194-241`) и отдельные `preview_change_campaign_name`, `preview_pause_campaign`, `preview_resume_campaign`, `preview_change_campaign_budget` попадают в `McpPreviewService.create()` (`mcp.service.ts:427-430,1039-1080,1493-1522`). Preview хранится в `McpPreview` (`packages/database/prisma/schema.prisma:557-579`): workspace, service-token principal, provider, account, object ID, operation, JSON payload/diff, SHA-256 digest случайного `hmpp_` token, `expiresAt`, `confirmedAt`, `consumedAt`. TTL в коде — **10 минут**, не 30 (`mcp-preview.service.ts:76-77`). Обычный preview симулированный и не вызывает Meta mutate; для узкого App Review rename до preview читается реальное состояние Meta.

`confirm_preview` → `McpPreviewService.confirm()` (`mcp.service.ts:1081-1092`, `mcp-preview.service.ts:193-339`) требует write scope и тот же service token, атомарно устанавливает `confirmedAt`. Это подтверждение **через MCP credential**, не самостоятельное действие человека в браузере. `commit_preview`/Meta aliases → `McpPreviewService.commit()` (`mcp.service.ts:1093-1110`, `mcp-preview.service.ts:342-482`): проверка scope, TTL и confirmation, одноразовый `consumedAt` через `updateMany`, затем policy. Общий policy разрешает только allowlisted Meta account/object/operation; отдельный `meta-app-review-write.policy.ts` разрешает ещё более узкое переименование подготовленной PAUSED-кампании. В контролируемом сценарии перечитывается состояние перед mutate и после него (`mcp-preview.service.ts:509-685`).

Журнал — `AuditEvent` (`schema.prisma:582-600`) и `AuditService`: `mcp_preview_created`, `mcp_preview_confirmed`, `mcp_commit_blocked/completed/failed`, подробные `meta_app_review_rename_*`. Это не универсальный per-operation Google журнал с raw provider response/request_id и готовым rollback tool. Текущие `McpPreview`/policy/commit нельзя считать готовым каркасом Google Ads из этапа 6; Meta не менять.

## 4. Google Ads provider: client, версия, OAuth, MCC, developer token

Текущий V2 adapter `apps/api/src/providers/adapters/google.ads.ts` использует **прямой REST через `fetch`/`providerJson()`**, не Google client library: OAuth token endpoint, `customers:listAccessibleCustomers` и `customers/{id}/googleAds:searchStream`. URL строится в `apiBase()` (`google.ads.ts:497-499`). `PROVIDER_GOOGLE_API_VERSION` имеет default `v24` (`packages/config/src/index.ts:42-45`, `.env.v2.example:23`); legacy alias `AD_MCP_GOOGLE_ADS_API_VERSION` может его переопределить (`index.ts:266-268`). Точную версию, реально выставленную в production env, без доступа к этому env подтвердить нельзя; её не меняли. Старый `.env.example:56` всё ещё предлагает `v20`, что не является default V2.

OAuth: `GoogleAdsAdapter.authorizationUrl()` запрашивает `https://www.googleapis.com/auth/adwords`, `access_type=offline`, `prompt=consent`; `exchangeCode()`/`refreshCredentials()` работают с `https://oauth2.googleapis.com/token` (`google.ads.ts:67-141`). `ProviderService.startOAuth()/completeOAuthForState()` (`provider.service.ts:104-349`) связывает state с user/session/workspace, сохраняет зашифрованный credential в `ProviderCredential` и открытые scope metadata в connection; read refresh выполняется в `provider.service.ts:1464-1520`. Утверждения плана о Google approval/In production/ролях не проверялись в Console.

MCC: adapter читает доступные customer IDs, делает `customer_client` query для manager и сохраняет дочерним аккаунтам `managerCustomerId`/`loginCustomerId` (`google.ads.ts:143-196,383-414`); `ProviderService.persistAccounts()/readContext()` (`provider.service.ts:1522-1572,1393-1425`) переносит это в account metadata/read context. `headers()` (`google.ads.ts:481-493`) посылает `login-customer-id` без дефисов, если он есть. Источник — metadata credential/account либо `PROVIDER_GOOGLE_LOGIN_CUSTOMER_ID`/alias `AD_MCP_GOOGLE_ADS_LOGIN_CUSTOMER_ID` (`packages/config/src/index.ts:39-44,263-265`). Целевой `customerId` в URL остаётся ID клиентского кабинета; это не ID MCC. [Google о login-customer-id](https://developers.google.com/google-ads/api/docs/concepts/call-structure).

Сейчас V2 `headers()` **всегда добавляет `developer-token` и `required()` требует непустой конфиг**, а constructor считает его условием `available` (`google.ads.ts:57-65,481-493`). [Google объявил sunset 09.09.2026](https://developers.google.com/google-ads/api/docs/api-policy/developer-token): доступ теперь связан с Google Cloud project; сервер пока игнорирует заголовок, будущая major version будет отвергать. Для V2 REST **минимальной версии библиотеки нет** — библиотека не используется; убрать локальное требование/заголовок можно без dependency upgrade, но это задача этапа 2, сейчас код не менялся. В legacy Python V1 (`pyproject.toml:25`, `src/ad_mcp/providers/google_ads/account_read.py`, `reporting.py`, `detailed_reports.py`) указан `google-ads>=25.1.0` без lock и в `load_from_dict()` передаётся developer token; для отказа от локальной проверки в этой **другой** библиотеке официальный минимум — `google-ads-python v32.0.0` ([Google client libraries](https://developers.google.com/google-ads/api/docs/client-libs)). Установленная/production версия V1 не проверялась, dependency не обновлялась.

## Google Ads API reality / расхождения и stop conditions

Официальная [v24 field reference](https://developers.google.com/google-ads/api/fields/v24/overview) содержит все 10 названных в задаче ресурсов: [`keyword_view`](https://developers.google.com/google-ads/api/fields/v24/keyword_view), [`ad_group_criterion`](https://developers.google.com/google-ads/api/fields/v24/ad_group_criterion), [`search_term_view`](https://developers.google.com/google-ads/api/fields/v24/search_term_view), [`campaign_search_term_insight`](https://developers.google.com/google-ads/api/fields/v24/campaign_search_term_insight), [`campaign_search_term_view`](https://developers.google.com/google-ads/api/fields/v24/campaign_search_term_view), [`campaign_criterion`](https://developers.google.com/google-ads/api/fields/v24/campaign_criterion), [`shared_set`](https://developers.google.com/google-ads/api/fields/v24/shared_set), [`shared_criterion`](https://developers.google.com/google-ads/api/fields/v24/shared_criterion), [`campaign_shared_set`](https://developers.google.com/google-ads/api/fields/v24/campaign_shared_set), [`campaign_budget`](https://developers.google.com/google-ads/api/fields/v24/campaign_budget). Именованные поля плана (`ad_group_criterion` keyword/status/quality/bid/URL, `search_term_view.status`, keyword segments, budget amount/period/shared flag, shared-set fields) найдены в соответствующих v24 references; `SearchTermTargetingStatus.NONE` существует ([enum v24](https://developers.google.com/google-ads/api/reference/rpc/v24/SearchTermTargetingStatusEnum.SearchTermTargetingStatus)). Комбинации полей целых GAQL запросов **не прогонялись** через API/GoogleAdsFieldService — это остаётся проверкой будущих этапов. [`campaign_search_term_view`](https://developers.google.com/google-ads/api/fields/v24/campaign_search_term_view) предупреждает: keyword-related segments исключат Performance Max строки.

Подтверждённые расхождения с планом: V2 — REST, не client library; Google developer token всё ещё обязателен локально и отправляется, вопреки новой политике Google; generic Meta preview — 10 минут и service-token confirm, не 30-минутный per-operation Google workflow; общий Google preview возможен как симуляция, но Google commit закрыт; исходные live-check цифры/Google Console status не проверялись. [Google о `validate_only` и `partial_failure`](https://developers.google.com/google-ads/api/docs/best-practices/partial-failures): в будущем successful операции при partial failure могут сохраниться, это не rollback. Плановый `GoogleAdsService.Mutate` поддерживает mixed resource operations и partial failure ([best practices](https://developers.google.com/google-ads/api/docs/mutating/best-practices)); ни один mutate/validate_only сейчас не вызывался.

**STOP CONDITION:** этап 6 по самому плану требует изменения общей DB schema и preview/commit, используемых Meta. Кроме того, архитектура общего preview в production отличается от описанного 30-минутного Google workflow, а Public MCP ветка уже меняет те же сущности. Остановиться до архитектурного решения человека; этапы 2–9 в этой задаче не выполнять.
