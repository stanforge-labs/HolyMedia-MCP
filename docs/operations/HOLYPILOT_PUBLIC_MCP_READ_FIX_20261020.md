# HolyPilot public MCP READ: API-only correction and release gate

## Evidence boundary

- Inspected production source baseline `a00817b746211a295bcb966f7fd7ef12cd6178fb` against feature branch `codex/qrs-test-auth-recovery`. The public READ inventory at that baseline reused the legacy permissive `McpService.tools()` schemas. It was possible to advertise the four affected tools without `provider` or `account_id`; the runtime then failed inside `account()` and the MCP controller returned the generic HolyMedia failure. This is reproducible from source and local tests.
- The reported Claude Pro result is a client-observed failure. Saved acceptance documents do **not** contain the four exact production request payloads, request IDs or corresponding API exceptions. The exact cause of each historical invocation cannot be proved offline. In particular, `get_account_status` uses the provider-account DB and never calls Google; its failure does not establish a Google OAuth fault. For the other three, malformed arguments, workspace/account denial, billing, provider OAuth, provider availability and quota are distinguishable only after the corrected response or correlated production evidence.
- A successful `list_ad_accounts` or `list_connected_resources` proves a scoped database listing only. Each account-scoped call independently checks workspace, connection state and the principal account allowlist. Stored `ACTIVE` status is not live OAuth validation.

## Code change

- Public `tools/list` now advertises closed JSON Schemas with canonical `provider` and string `account_id` for the four reported tools and related account reads. Advertising account enumeration is limited to advertising providers; account status can also inspect connected GA4/Search Console DB records. Dates use `start_date` / `end_date`, valid `YYYY-MM-DD`, paired and at most 366 inclusive days; campaign page limits are 1–500. Remaining formerly open public READ schemas are closed to their implemented fields. Private MCP retains its old schemas and aliases.
- Public `tools/call` enforces the advertised schema before billing or provider dispatch. It rejects numeric IDs, guessed date keys, unexpected fields, invalid periods and oversized limits. Error results use safe machine codes (`invalid_arguments`, `account_unavailable`, `permission_denied`, `billing_unavailable`, `quota_exceeded`, `provider_auth_expired`, `provider_unavailable`, `rate_limited`, `internal_error`). Upstream response bodies, token values, stack traces and arbitrary argument values are not returned. Expired HolyMedia OAuth bearer credentials still use the existing HTTP 401 OAuth challenge before tool execution.
- `get_account_status` returns `source: v2_database_provider_account` and `live_connection_checked: false`. `get_status_summary` reports `complete: false` and a cursor when a provider campaign page is truncated; it attaches item provenance only when returned by the successful adapter read.
- No write tool, provider mutation gate, OAuth credential, billing policy or Claude Plugin/Skill is changed.

## API-only release sequence — separate owner approval required

1. Confirm the final source SHA and exact-source Linux CI PASS. Build or select an immutable **API-only** image with OCI revision equal to that SHA; record its digest. No Web/Worker image change.
2. At release time, perform a short read-only check of the running production API source/image, pending approvals/commits/OAuth, disk/RAM/swap/PSI/OOM and health. Do not assume the feature branch is already deployed. Confirm rollback image is present, protected configuration/DB backups exist and required resource guards pass.
3. Obtain specific production API-only cutover authorization. Keep Google Ads writes default-OFF. Replace only API using the existing guarded release mechanism, preserving the original image/configuration for one-step rollback. Do not run old and new APIs in parallel if capacity is insufficient.
4. Verify `/health`, `/ready`, OAuth metadata/login/consent/approval, production Web, private MCP and public `tools/list`. For one selected owned account, run the short READ check below. Verify DB-only status source, campaign result or a typed safe error, and absence of provider writes. Run all existing post-start resource guards; on any critical failure, restore the original API once and stop.

**Short Claude READ check after approved release:** reconnect the existing HolyPilot connector, call `list_ad_accounts`, then call `get_account_status` using exactly the returned `provider` and string `account_id`. Expect `source=v2_database_provider_account`, `live_connection_checked=false`, and a status without a Google network claim. Next, call `list_campaigns` with the same two fields and `limit=5`; a successful result is provider READ evidence, while a typed error directs the next diagnosis. Record only redacted tool inputs, machine codes and request time; do not copy tokens or client data into public CI/Git.

No production operation is authorized by this document. A historical Claude failure must not be reclassified as resolved LIVE before the approved API-only release and actual Claude retest.
